Third-party wallet compatibility was checked on 2026-11-14: Meteor Wallet (browser extension) on `captab.testnet` connected to captab.xyz, signed `accept_grant` ([tx](https://testnet.nearblocks.io/txns/GzpcBV1oLdp2suupsWdKYJEdB5bvb3oFMsk8ibxoKLWj)) and `claim_vested` ([tx](https://testnet.nearblocks.io/txns/z8Z4BK38ny7ttDScvrZBH2SxbabDiu2UXTeyzfV73md)), and completed an NEP-413 sign-in. The seeded founder, grant, snapshot, funding, worker failure, retry, final token-balance checks, browser-driven DAO pause/resume, and live sponsored claim have passed on testnet. The browser test wallet signs in a local Node process; it does not establish compatibility with an external wallet. Do not put private keys in this file or the manifest.

The MVP deliberately limits history to app-submitted transactions, uses persistent single-host SQLite, has no automatic recovery for a transfer whose callback failed, and treats ownership units and TESTUSD as fictional. These limits remain visible in the [runbook](RUNBOOK.md) and app. A production system would need a separate design for complete indexing, callback recovery, confidentiality, legal ownership, and upgrades.
