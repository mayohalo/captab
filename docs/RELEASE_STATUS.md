The remaining live sequence is: import council, operator, and contributor keys into separate testnet wallet profiles; repeat key journeys in the browser with wallet signatures, including a sponsored claim on testnet; inspect those receipt chains; review deployment-key removal, refresh the manifest, record the live demo, and package the submission. The seeded founder, grant, snapshot, funding, worker failure, retry, and final token-balance checks have already passed on testnet using local signers. Do not put private keys in this file or the manifest.

The MVP deliberately limits history to app-submitted transactions, uses persistent single-host SQLite, has no automatic recovery for a transfer whose callback failed, and treats ownership units and TESTUSD as fictional. These limits remain visible in the [runbook](RUNBOOK.md) and app. A production system would need a separate design for complete indexing, callback recovery, confidentiality, legal ownership, and upgrades.
